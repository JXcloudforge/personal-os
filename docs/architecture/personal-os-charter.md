# Personal OS 长期产品宪章（R0 提案）

状态：R0 设计提案，尚待负责人批准。日期：2026-10-19。

本宪章描述长期产品方向，不代表当前功能、部署能力或数据模型已经实现。它不改变现有 v0.3.3 发布记录，也不扩大当前 `develop/v0.4` 的开发范围。

## 使命

Personal OS 的长期定位是 **Personal Intelligence, Decision & Action Operating System**：以真实证据、显式不确定性、可解释的价值判断、用户授权和现实反馈，帮助个人理解现实、形成有意义的目标、组织资源并扩大自主选择权。

核心循环：

```text
建立世界模型 → 用证据更新信念 → 比较决策与机会成本 → 经授权组织行动
      ↑                                                    ↓
      └────── 结果反馈、偏差复盘与资源/约束变化 ────────────┘
```

系统价值不以任务数、知识卡数、聊天次数或 AI 自动化比例衡量。评价问题是：

- 对现实的认知与预测是否随证据变得更可靠？
- 行动是否产生事先定义的结果？结果和预测差距多大？
- 时间、资金、计算与注意力是否用于价值更高的选择？
- 技术能力、资产、机会与合作资源是否积累？
- 风险、可逆性和自主选择权是否得到改善？

这些是长期评价维度，不是现有系统已经采集或证明的指标。没有足够样本时应返回 UNKNOWN；不得用代理指标伪装个人成长或因果效果。

## 产品原则

1. **用户拥有控制权。** 用户决定目标和价值偏好；关键决策由用户确认；外部执行、数据外发和付费模型调用必须符合现有授权边界。
2. **证据与推断分开。** 记录来源、时间、范围、可信状态和数据缺口。模型文字不自动成为事实、证据或用户授权。
3. **概率可解释。** 基础率声明参照群体和口径；数值更新由确定性、可测试逻辑完成，并保留输入和计算版本。证据不足时不生成精确概率。
4. **效用不等于概率。** 结果概率、成本、偏好、风险、机会成本和未来选择权分别呈现，不将它们藏入一个不可解释的分数。
5. **行动可审计、可恢复。** 正式任务仍只经 Task Service 创建/修改；Agent 只产生可编辑提案，保留审批、幂等、失败和审计行为。
6. **反馈不自动美化。** 区分任务完成、目标达成、能力增长和因果证据；单次成功或失败均不自动代表长期趋势。
7. **增量演进。** 保留 FastAPI、SQLAlchemy、SQLite、Alembic、React、Vite、TypeScript、pnpm、Windows 本地部署与 Tailscale 私有 HTTPS。六个能力域是逻辑边界，不要求拆成独立服务。
8. **保护既有记录。** 新模型和迁移须另行批准；不得以愿景升级重建或覆盖任务、知识、学习、健康、复盘和 Agent 历史。

## 六个逻辑能力域

| 域 | 长期职责 | 初步复用路径 |
|---|---|---|
| G01 Goal & Constraint Model | 目标、价值偏好、时间范围、资金预算、当前/期望资源、硬约束与软偏好 | 先复用 `UserGoal`、用户设置和 Task 字段；资源/偏好缺少明确语义时再设计增量契约 |
| W01 World Model & Bayesian Belief | 假设、证据、参照群体、先验/似然/后验、依赖关系和版本历史 | Knowledge 提供知识/来源入口；不把知识卡直接等同于证据或信念 |
| D01 Decision Engine | 竞争方案、预期效用、机会成本、风险、可逆性、信息价值和实验建议 | 首次实现为独立决策域；数值计算使用纯函数和版本化 DTO |
| A01 Action Orchestrator | 将已确认行动转成受控的可执行任务 | 复用 Proposal Service、Tool Registry、Agent Runner、Task Service 与幂等操作 |
| F01 Feedback & Learning | 预测、结果、证据、偏差、资源变化和审慎校准 | 复用 Daily/Weekly Review、TaskEvidence、Knowledge Feedback；不将自报升级为独立核验 |
| I01 External Intelligence Gateway | 接收未来外部情报系统的标准化候选信号 | 仅设计版本化输入契约；不接外部采集器数据库，不在 R0 实现采集 |

## 明确不代表

- 当前系统已经具备贝叶斯世界模型、决策效用计算或个人能力增长评估。
- 当前的 DailyReview、知识来源或 Agent Run 已是完整的现实结果验证链。
- 需要向量数据库、微服务、消息队列、新前端框架或外部情报采集器。
- AI 可以替用户设定目标、审批任务、写入真实结果或代表用户执行外部操作。
